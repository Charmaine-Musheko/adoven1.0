Adoven DigitalOcean Data Setup Report

Date: 2026-05-17

Server: DigitalOcean Droplet 164.92.194.34

Goal: Connect the Flutter Analytics page to real energy telemetry stored on the DigitalOcean Droplet.

Starting Problem

The Flutter app was trying to load API data from https://localhost:7234/api. That worked only for a local backend and failed from Safari/mobile because no API was running locally or publicly.

Server/API Work Done

  1. Installed .NET 8 SDK and Nginx on the Droplet.
  2. Created a minimal ASP.NET Core API at /opt/adoven-api/AdovenApi.
  3. Opened/used port 7234 for the test API.
  4. Connected the API to SQL Server in Docker via localhost,1433.
  5. Added the Microsoft.Data.SqlClient package.
  6. Created /api/analytics to query real rows from AdovenDB.dbo.EnergyData.

Flutter App Changes

  1. Changed the API base URL from localhost to the Droplet API: 
    http://164.92.194.34:7234/api
  2. Allowed Android cleartext HTTP traffic for the current Droplet test endpoint.
  3. Added an Analytics repository that calls /api/analytics.
  4. Reworked the Analytics page from hardcoded demo utility bills into a real energy telemetry dashboard.

Analytics Page Now Shows

  • Current live power in watts/kW.
  • kWh used in the last 24 hours.
  • kWh used in the last 30 days.
  • Estimated energy cost using a temporary N$2.50/kWh rate.
  • Voltage, current, imported kWh, peak power, average power, reading count, and last updated time.

Important Notes

  • The API is currently run manually with dotnet run. For production, create a systemd service so it starts after reboot.
  • The endpoint currently uses plain HTTP and port 7234. For production, put it behind Nginx with HTTPS on port 443.
  • The SQL password appeared in the old bridge script. Rotate it later and move secrets into environment variables.
  • The cost calculation uses a temporary rate of N$2.50/kWh. Replace it with the real tariff when available.
